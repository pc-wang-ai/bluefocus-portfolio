我参与推进的几项功能

让全部方剂能从页面查到

原入口只有 3 个快捷案例。我参与明确按名称、别名、药味检索的要求，复用已有检索服务，而不再维护固定列表；用“阳旦汤 → 桂枝汤”及缺数据方剂检查结果。

查完资料后能保存和继续整理

参与设计条目 → 基因 → 靶点 → 成分的下钻，以及笔记版本和报告章节排序。协同 AI 排查草稿总是新建、切换笔记残留旧内容等问题，再检查重开和下载。

比较结果能解释，也能检查

参与核对靶点分类、缺失层和排除记录的展示要求；用完整、部分和缺失三组专题检查图表、矩阵与导出一致性。

代码由人工与 AI 协作完成，个人工作采用参与式描述。

为什么做这个平台

研究一首方剂时，需要先找组成，再查成分、实验记录和相关分析。资料分散在不同表格和报告里，核对一次往往要反复切换文件。

我想减少的麻烦

同名或别名需要重新确认；查到一条结果后还要找出处；有些方剂缺少计算结果，容易与“没有显著结果”混淆。

平台怎样处理

我参与把对象和来源放在相邻页面，支持从方剂继续查看成分和实验靶点。缺失、输入不足和身份受限分别显示，研究结果可以保存和导出。

主要面向需要整理和比较中药科研资料的使用者。

系统怎样组织数据和功能

界面主要用 Python 和 Streamlit 编写。项目按下面的顺序组织数据读取、查询与展示，研究记录保存在 SQLite 中。

资料来源

本草与方剂资料、ChEMBL 实验记录，以及 GO、Reactome、STRING 分析结果。

整理与读取

对齐实体编号和关系，保留来源、数据版本与缺失状态；读取已有计算结果。

查询与研究

检索方剂、查看详情和来源，按基因或通路反查方剂，再做比较或专题。

AI 功能

程序先检索资料，DeepSeek 可调用只读工具补充查询，再整理回答并记录引用。

界面与保存

Streamlit 展示表格和图表，SQLite 保存研究记录，支持报告、CSV 和 ZIP 导出。

P34 全仓测试记录

为什么需要修

三方剂比较中出现 Unchecked、NON-PROTEIN TARGET 和细胞系名称。这些条目没有蛋白组件，若混入比较，会把非蛋白记录当成共同作用靶点。

如何判断分类

我参与核对名称与 ChEMBL 组件关系。只有可追溯到蛋白组件的目标进入矩阵；其他记录单列原因与数量，原活性数据保留。

怎样确认修复正确

指定三方剂案例排除 1,791 条非蛋白活性记录，共有蛋白靶点为 60。检查矩阵仅含蛋白、排除数与覆盖表合计一致，并核对图表和导出。

案例 F0294 / F0044 / F0303；1,791 = 331 条占位 + 1,460 条细胞系活性，为专题内按方剂汇总的记录数，不是唯一靶点数。

统计采用 P34 版本验收记录。三组核查均 8/8，浏览器 9/9。457 首中 11 首输入不足；GO/Reactome 有结果 445 首，STRING 446 首。

应用设想　企业品牌资料检索与内容审核

假设运营同事要为某款产品写一段活动文案，需要确认卖点、适用范围和当前版本的品牌用语。

1　查资料

输入产品名和问题，返回产品说明、品牌手册中的相关段落，同时标出文件版本、页码与生效日期。

2　起草与检查

根据资料生成草稿，把缺少依据的卖点、过期描述和禁用词逐项标出，点击提示可回看原文。

3　人工确认

审核人修改并确认，保存引用、修改记录与审核版本。未经确认的草稿不进入发布环节。
